# Release Notes

Формат: найновіший реліз зверху. Нотатки пишуться мовою користувача (Клієнт, Менеджер, Логіст), а не мовою розробника. Стани й назви беруться з [таблиці контрактів](api-contracts.md).

Статус: **v1.0 MVP ще не випущено**. Нижче чернетка, що фіксує запланований обсяг; перед релізом кожен пункт позначають за результатом приймання ([UAT-чекліст](confluence/parts/24-uat-checklist.pdf)).

## v1.0 MVP (план: 13.12.2026)

Повна угода від заявки до доставки (спринти 1–3 за [планом](confluence/parts/22-commercial-proposal-and-budget.pdf)).

### Нове

Клієнт:
- [ ] Вхід за роллю, перегляд каталогу авто з фільтрами
- [ ] Створення, редагування та скасування заявки на підбір
- [ ] Надання документів на запит менеджера
- [ ] Оплата інвойсу, відстеження доставки, підтвердження отримання

Менеджер:
- [ ] Перевірка заявки, запит документів
- [ ] Ставка на аукціоні, фіксація результату
- [ ] Виставлення інвойсу, підтвердження або відхилення оплати
- [ ] Штраф за протермінування оплати

Логіст:
- [ ] Призначення перевізника, оформлення митних документів
- [ ] Оновлення статусу доставки

### Відомі обмеження

- Аукціон, оплата та фотозвіти симулюються всередині системи, інтеграцій із зовнішніми сервісами немає.
- Платежі проводяться поза системою; менеджер лише фіксує оплату.
- Хостинг і зовнішні сервіси не входять в обсяг.

### Зміни, що впливають на дані

- Заповнити, якщо реліз змінює схему БД або переліки (`OrderStatus`, `CarStatus`): вказати міграцію й чи потрібен відкат.

### Перевірка перед релізом

- [ ] Усі пункти Must в UAT-чеклісті пройдено
- [ ] Перевірено кожен статус життєвого циклу авто й заявки (урок із [post-mortem](confluence/parts/12-post-mortem-v1.0-mvp.pdf))
- [ ] Dry-run відкату виконано
- [ ] У репозиторії немає ключів, паролів і реальних даних
- [ ] Відомі дефекти й обхідні шляхи перелічені в цьому документі
